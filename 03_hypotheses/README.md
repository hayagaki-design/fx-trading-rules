# 仮説管理

HYPOTHESISは未検証の説明・行動候補。OBSERVEDをそのまま正式ルールへ変換しない。

[仮説台帳](active-hypotheses.md)でIDを予約し、具体的なセットアップは[ルールテンプレート](../07_templates/rule-template.md)で個別文書を作る。テンプレートのRule ID欄には仮説段階ではHYP IDを使用する。

## TESTING開始前に固定すること

- 通貨ペア・時間足・対象環境・期間・データソース。
- 誰が見ても同じ判定になる条件・トリガー・否定条件・見送り条件。
- エントリー・決済の約定仮定とコスト、部分決済の扱い。
- 採用に必要な最低件数・期待値・連敗等の閾値と判定方法。
- 対象事例の抽出方法、連続・重複シグナルの数え方、未使用期間での再確認方法。

必要項目が1つでも未設定ならHYPOTHESISを維持する。全項目を固定した日時（タイムゾーン付き）をTest Criteria Fixed Atに記録してからTESTINGへ進む。観測2件と検証2回は同義ではない。

## 変更・矛盾記録

各仮説に「日付 / 旧状態・版 / 新状態・版 / 理由 / 証拠 / 判断者」を追記する。条件変更時は過去データを新条件の成績に無条件で混ぜない。

統合時は元IDを残し、統合先と差分を記録する。矛盾がある場合は対象環境・優先順位を明記し、未解消なら昇格を保留する。

## バージョンの保存

初期版は全件Version: v0.1。HYP-001〜007の検証条件とPromotion Criteriaは未固定。HYP-008のみ2026-09-11T15:18:37+09:00に初回固定しTESTINGへ移行した。リポジトリv0.1の確定と、検証条件の固定は別である。

条件・採用基準の変更時は旧文書を保持し、新しい版の文書（例: HYP-008-v0.2.md）を作成する。複数仮説を含む原則文書も旧版の記述を残し、変更対象のHYP IDについて新版を別文書にする。台帳から各版を参照できるようにする。

新版にはVersion、Test Criteria Fixed At、Promotion Criteria、Version History、Change Reasonを記載し、変更日・理由・差分・旧版の参照先を残す。旧版の検証結果を削除・置換しない。新条件で過去データを再評価した場合は再評価であることを明示し、新版の結果として別保存する。過去データへの適合だけで採用せず、未使用データでも検証する。
