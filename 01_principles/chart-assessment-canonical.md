# チャート判定の運用正本

会話中の表示や運用がずれた場合は本書に戻る。表示規約で仮説の固定条件・採点規約を変更しない。

## 対象と判定

- 5分足：[HYP-009 v0.1](../03_hypotheses/HYP-009-5m-impulse-pullback-continuation.md)。
- 15分足：[HYP-008 v0.1](../03_hypotheses/HYP-008-failed-high-breakdown-retest.md)。
- 形成中の足ではENTRY判定を出さず、確定足のみ使用する。
- 時間足・価格・確定状態が読めなければ推測せず確認する。必要価格が読めない場合は該当足をタップした画像を依頼する。
- 判定は短く淡々とし、余計な解説を挟まない。

| 状態 | 基本表示 |
| --- | --- |
| 条件に該当しない | NO SETUP |
| 形成・確認待ち | WATCH — まだ入らない |
| 確定足でトリガー成立、注文可能条件も確認済み | TRIGGERED — ENTRY |
| 形の無効化 | INVALID — この形は終了 |

価格トリガーだけ成立しても、スプレッド・イベント・残高・数量・日次停止等で注文不可または必要情報未確認ならENTRYと案内しない。「TRIGGERED — NO TRADE：理由」または「WATCH — まだ入らない：確認項目」と短く示す。仮想検証の価格シグナルと実注文の可否は分離して記録する。

ENTRY表示時はEntry / SL / SL幅pips / TP / risk% / 最大許容損失額 / 最大通貨数 / GMO注文数量を必要最小限で添える。不明値を推測で埋めない。[資金管理](risk-management.md)と各仮説の低いリスク上限を優先する。

## 保有後

- HOLD/継続：保有が確認され、出口条件未成立。
- TP：利確が確認できた場合。
- SL：損切りが確認できた場合。
- タイムストップは「TIME STOP — 期限決済」と表示し、TPやSLへ読み替えない。

チャート上の到達と実際の約定は区別する。約定が未確認ならその旨だけを添え、実決済を断定しない。実注文・デモ・仮想のどれを判定しているかを明示する。

通常009は1.5R固定利確のまま。[1.5Rロック派生](../03_hypotheses/HYP-009-lock-1.5R-v0.1.md)は対象保有についての明示宣言と変更有効化が確認された場合だけ別記する。「HOLD/継続」という表示だけで派生へ移行しない。派生はHYPOTHESISであり、通常009の採点条件には適用しない。

履歴：2026-09-15、ユーザー指定の会話運用を正本として記録。固定条件の変更なし。

## HYP-009判定の記録手順（2026-09-15補足）

表示の先頭は ⚪ NO SETUP / 🟡 WATCH / 🟢 TRIGGERED / 🔴 INVALID のいずれかを原則とする。続けて「方向／確定足／状況／今やること」を短く表示する。形成中足は🟡 WATCHであり、🟢 TRIGGEREDを出さない。足ラベルが始値か終値かを確認する。

🟢 TRIGGEREDの場合だけ、確定トリガー足の方向・仮想Entry終値・初期SL・通常009の固定1.5R TP・Risk pips・Case IDを直ちに示す。残高が分かればrisk%・最大許容損失額・発注単位に切り下げた数量も示す。既存の注文可否確認項目が未確認ならTRIGGERED — NO TRADEまたはWATCHの理由を明記する。価格シグナルが後で判明しても現在価格への追いかけEntryを案内せず、実際の約定は仮想ログと分ける。

画像で閾値価格が正確に読めないときは対象足のOHLC表示を使い、推測で数値を埋めない。詳細は[検証管理の運用](../06_statistics/HYP-009-observation-operations.md)。この補足は表示・記録方法であり、HYP-009 v0.1の売買条件と派生の適用条件を変えない。
